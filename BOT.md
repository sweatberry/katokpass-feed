# Бот для агентств-партнёров

Один бот делает две вещи:

- **Горящий рейс.** Агентство присылает сообщение в обычном формате → бот проверяет его
  и публикует в канал KatokPass → сборщик забирает рейс в ленту приложения.
- **Горящий тур** (перелёт + отель + питание + страховка + трансфер). Агентство отправляет
  `/tur`, бот задаёт 10 вопросов по шагам и добавляет тур в `docs/tours.json` — из этого
  файла приложение показывает вкладку «Туры».

Сервер не нужен: бот работает на том же расписании GitHub Actions, что и сбор, раз в 15 минут.
Поэтому ответ от бота приходит не мгновенно, а в течение четверти часа — так и написано в его подсказках.

## 1. Создать бота
1. В Telegram откройте @BotFather → `/newbot`.
2. Имя: `KatokPass для агентств`. Адрес: например `katokpass_partners_bot`.
3. BotFather пришлёт токен вида `8123456789:AAH...`. Это пароль — никому не пересылайте
   и не вставляйте в переписку, только в секреты GitHub.
4. Там же: `/setdescription` — «Публикация горящих рейсов и туров в приложении KatokPass».

## 2. Дать боту доступ к каналу
Канал → Управление → Администраторы → Добавить бота с правом «Публикация сообщений».

## 3. Добавить секрет на GitHub
Репозиторий → Settings → Secrets and variables → Actions → New repository secret:
- имя `TG_BOT_TOKEN`, значение — токен от BotFather.

## 4. Дописать три строки в sources.json
Свой файл не переписывайте целиком (в нём номер вашего канала) — добавьте строки:

```json
  "botChannel": "-1001234567890",
  "adminChat": "123456789",
  "toursTtlDays": 5,
```

- `botChannel` — куда бот публикует рейсы агентств (тот же номер, что у источника, с `-100`).
- `adminChat` — ваш личный чат с ботом: туда приходят туры новых агентств на проверку.
  Номер узнаете так: напишите боту `/id`, он ответит числом.
- `toursTtlDays` — сколько дней тур живёт в приложении (по умолчанию 5).

## 5. Обновить workflow
В `.github/workflows/collect.yml` перед шагом «Прочитать канал» добавьте:

```yaml
      - name: Принять рейсы и туры от агентств
        env:
          TG_BOT_TOKEN: ${{ secrets.TG_BOT_TOKEN }}
        run: python collector/agency_bot.py
```

А шаг сохранения замените на такой — он сохраняет и рейсы, и туры, и фотографии отелей:

```yaml
      - name: Сохранить данные
        run: |
          git add -A docs
          if git diff --cached --quiet; then
            echo "Изменений нет"
            exit 0
          fi
          git config user.name "katokpass-bot"
          git config user.email "katokpass-bot@users.noreply.github.com"
          git commit -m "Обновить рейсы и туры"
          git push
```

Готовый файл целиком лежит рядом: `workflow-collect.yml`.

## 6. Подключить агентство
1. Партнёр открывает бота и отправляет `/id` — бот отвечает номером чата.
2. Впишите его в `agencies.json`:

```json
  "agencies": [
    { "name": "Название агентства", "chatId": "123456789",
      "trusted": false, "whatsApp": "77011112233", "enabled": true }
  ]
```

- `whatsApp` — номер агентства. Заявки по его турам идут напрямую ему, а не вам.
  У рейсов иначе: они идут на общий номер из `sources.json`.
- `trusted: false` — новый партнёр: его туры сначала приходят вам на проверку.
  Когда убедитесь, что он пишет аккуратно, поставьте `true` — дальше публикуется сразу.
- `enabled: false` — временно отключить партнёра, не удаляя.

Всё, что присылают незнакомые чаты, бот не публикует: он отвечает их номером и ждёт вашего решения.

## Формат рейса

```
Алматы - Анталья
S 22.09 - 89000 (4)
S 22.09 - 29.09 = 165000

S - SCAT
Багаж 20 + 5 кг
```

Первая строка — маршрут. Дальше «код авиакомпании, дата, цена», в скобках число мест.
Две даты со знаком `=` — туда-обратно. Внизу расшифровка кодов и багаж.
Цены закупочные: наценку приложение добавляет само.

## Как добавляется тур

Партнёр отправляет `/tur`, бот спрашивает по одному:

1. страна → 2. курорт → 3. отель → 4. звёзды (1–5) → 5. город вылета →
6. дата вылета (`22.10`) → 7. ночей → 8. питание (`AI`, `UAI`, `FB`, `HB`, `BB`, `RO`) →
9. цена **за двоих целиком** → 10. фото отеля одной картинкой.

Каждый ответ проверяется: прошедшую дату, восемь звёзд или цену в 5 000 ₸ бот не примет
и переспросит. `/otmena` прерывает заполнение.

Дальше:
- партнёр с `trusted: true` — тур сразу в `docs/tours.json`, в приложении через 15 минут;
- новый партнёр — карточка и фото приходят вам в `adminChat` с кнопками
  **✅ Опубликовать** / **❌ Отклонить**. Нажатие обрабатывается при следующем запуске
  расписания, то есть в пределах 15 минут. При отказе фото удаляется из репозитория,
  а партнёр получает вежливое сообщение.

Страховка, трансфер, перелёт, проживание и питание добавляются в карточку сами —
это и есть «пакет», отдельных вопросов про них нет.

Фотографии лежат в `docs/photos/`, приложение берёт их оттуда по прямой ссылке.
Тур пропадает из приложения, когда истекает `toursTtlDays` или наступает день вылета.

## Что считает бот
В `docs/bot_state.json` копится статистика по каждому агентству: `flights` и `tours`.
Это основа для будущих счетов — видно, кто реально пользуется площадкой.
Там же лежат незаконченные черновики туров и заявки, ожидающие вашего решения.

## Проверка без Telegram
`python -m unittest discover -s tests` прогоняет весь разговор с ботом на подставном
Telegram: мастер туров, ошибки в ответах, модерацию, публикацию и отказ. 41 проверка.
